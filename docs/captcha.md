## 验证码功能说明与边界

### 请求重试机制
- **适用范围**：仅针对 V3 取题/静态资源请求与 V4 load/素材请求，最多尝试 3 次，退避间隔为 150ms、300ms，任务取消时立即停止。
- **触发条件**：仅在网络临时异常、空响应或 5xx 状态码时重试；4xx 与非法响应不重试。
- **不重放逻辑**：V3 ajax 与 V4 verify 答案提交不做原地重放；宿主每节点 5 次、整链 2 轮的重试策略保持不变。
- **未移植与已有项**：原项目基于 Go uTLS 的原生 TLS 指纹路线未移植；SVG 相关能力我方已具备。

### 配置提取与更新
- **运行方式**：使用 Node 24 执行 `scripts/update-captcha-config.mjs`（不增加运行时 Node 依赖）。
- **安全隔离**：远程 SDK 在隔离子进程、`vm`、空环境及 Node 权限限制下运行。
- **校验与写入**：若检测到 SDK 重写 `abo`、同构建多站结果不一致或与既有配置冲突，脚本将拒绝写入；更新时保留旧构建配置并执行原子写。
- **离线测试**：支持离线测试 sandbox，无需额外启动验证码 HTTP 服务。
- **自动检查**：GitHub Actions 每天北京时间 11:23 自动运行检查，仅在配置有变化时提交 `packages/captcha/resources/*-config.json`，检查失败不会覆盖现有配置。
