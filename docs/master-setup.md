# 设置主人

新安装完成 `bun run bootstrap` 后，终端默认具有主人权限。已有显式 `master` 配置不会被覆盖；`master: []` 表示主动关闭终端授权。

## 首位 QQ 主人

1. 前台运行 `bun run start`。协议端连接到启动日志中的 OneBot 11 地址。
2. 在机器人运行终端的 `>` 后输入：

   ```text
   #设置主人 <机器人QQ> <你的QQ>
   ```

   隔离调试网页默认机器人 QQ 为 `10000`、用户 QQ 为 `10001`，对应：

   ```text
   #设置主人 10000 10001
   ```

3. 终端回复「已设置为当前机器人的主人。」即完成，随后使用该 QQ 私聊机器人。授权写入本机 `config/other.yaml` 并立即生效，重启后保留。

网页修改模拟用户 QQ 只会切换发送身份，不会自动授予主人权限。`#状态`、`#帮助` 等普通指令可以先用于测试连通性。

## 已有主人添加另一位主人

1. 申请人私聊机器人发送 `#设置主人`，获得申请编号。
2. 现有主人在同一机器人的私聊中发送 `#设置主人验证码 <申请编号>`。
3. 将返回的验证码交给申请人，由申请人私聊发送 `#设置主人 <验证码>`。

申请 5 分钟有效，验证码仅能使用一次。未配置首位 QQ 主人时，必须先通过本机终端或配置文件完成首次授权。

## 手工配置与后台运行

也可在本机编辑 `config/other.yaml`，在已有内容中合并以下配置；不要覆盖其他已配置主人或字段：

```yaml
master:
  - stdin:stdin
  - "10000:10001"
masterQQ:
  - 10001
```

`master` 中的 `机器人QQ:主人QQ` 决定当前机器人的主人身份；`masterQQ` 为旧插件兼容项，不应单独依赖它授予宿主权限。配置通常会自动重载；显式关闭文件监听时需重启。

`bun run logs` 只查看日志，不能向后台机器人输入命令。首次授权可先前台设置，再 Ctrl+C 停止并使用 `bun run start:bg` 启动；也可直接编辑上述配置后重启后台。

主人配置属于本机私人配置，不提交到 Git。生产迁移保留已有账号绑定；不要把调试用 QQ 号写进生产配置。
